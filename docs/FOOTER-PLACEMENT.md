# Footer withdrawal-link placement

The legal withdrawal link is independent from the shared Joobox marketing attribution.

## Primary placement

On standard PrestaShop footers rendered by `ps_linklist`, the storefront normalizer:

1. selects the real site footer explicitly through `footer#footer` (not the earlier page-content `footer.page-footer` used by some themes);
2. finds the static Stores link by PrestaShop's stable anchor id prefix `link-static-page-stores-`;
3. falls back to comparing the localized Stores URL generated by `Link::getPageLink('stores')`;
4. creates a normal `<li>` immediately after the Stores `<li>`;
5. copies the neighbouring anchor classes, so the active theme controls typography, spacing, hover state and mobile collapse behaviour;
6. removes any legacy detached wrapper and duplicate legal links.

The module does not modify `ps_link_block`, `ps_link_block_lang` or another module's configuration.

## Fallback

`displayFooter` renders an accessible fallback link for browsers without JavaScript and for themes that do not expose a static Stores item. The JavaScript path removes that wrapper after exact placement succeeds.

`displayFooterPart1` is retained only as a no-output compatibility method and is removed from hook registrations during runtime synchronization. Some commercial themes render that hook inside the page-content footer, above the real site footer, so it is not a reliable visual placement point.

## Acceptance selector

For a standard `ps_linklist` footer, the following relationship must hold:

```javascript
const stores = document.querySelector(
  'footer#footer a[id^="link-static-page-stores-"]'
).closest('li');

stores.nextElementSibling.matches(
  'li[data-jooim-withdrawal-footer-item="1"]'
);
```

## Link target

The footer item points to the localized order-reference entry page, not directly to the manual statement form. For example, in Slovak it resolves to:

```text
/sk/odstupenie-od-zmluvy
```

The entry page still displays the direct withdrawal option for customers who cannot use the original order email. If friendly URL generation is unavailable, the module falls back to the language-neutral `entry&target=identify` controller.
